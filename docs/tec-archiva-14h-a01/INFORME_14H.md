# TEC-ARCHIVA · Certificación 14H

La candidata derivada 2.13.0-rc.3-14h certificó en un clon sintético el mecanismo de conciliación para un contexto con el identificador y los alias del destino. La decisión de actualización permanece NO_GO y la autorización NOT_GRANTED. El acceso administrativo histórico sigue pendiente del custodio.

La CLI exige una autorización Ed25519 para una operación concreta. El ejecutor anfitrión verifica contenedores, imágenes, redes, volúmenes, PostgreSQL, Redis y archivos antes de conceder acceso. Un registro SQLite con clave única confirma el consumo antes de emitir una segunda firma ligada al desafío del proceso. Los plazos máximos son cinco minutos para el permiso y treinta segundos para la atestación. Las claves privadas se guardaron fuera de las imágenes. El contenedor recibe una política pública de solo lectura y carece de acceso al motor Docker. [Documentación de Ed25519](https://cryptography.io/en/latest/hazmat/primitives/asymmetric/ed25519/)

El clon reprodujo el texto del proyecto histórico y los alias almacen_datos y mensajeria sobre recursos independientes. La invocación sin permiso devolvió 77. La invocación autorizada devolvió 0 y produjo evidencia de conciliación. El ensayo con un ID original se detuvo en la inspección de metadatos. Los cuatro originales permanecieron detenidos. No se montaron sus volúmenes ni se emitieron permisos para ellos.

Las 11 pruebas negativas cubrieron ausencia de autorización, confirmación genérica, cambio de nombre, destino incorrecto, recursos distintos, caducidad, operación fuera de alcance, evidencia faltante, ID original, reutilización y traslado de la atestación a otro proceso. Las nueve pruebas positivas verificaron la ejecución, idempotencia, concurrencia, revisión humana, rollback SQL, ausencia de cambios SQL y trazabilidad. Dos ejecutores con el mismo permiso devolvieron 0 y 77. Dos permisos distintos para la misma operación devolvieron 0 y 2. Los reintentos preservaron el recibo y la operación ambigua conservó su archivo.

Se ejecutaron 856 comprobaciones y pasaron todas, incluidos 21 controles de infraestructura. Las 824 comprobaciones de referencia se cubrieron con el contrato actualizado. Las expectativas previas de autorización implícita se actualizaron y los controles de la CLI se repitieron con permisos firmados. La regresión incluyó FastAPI, Celery, PostgreSQL, Redis, RBAC, sesiones, revocación, flujo documental, PDF/A y conciliación. La prueba de rollback 14H cubrió la transacción documental. La reversión entre versiones sigue respaldada por el ensayo aislado 14E y el plan de operación.

Durante el primer ensayo, PostgreSQL devolvió la IP con máscara /32 y el control la rechazó. Se normalizó la dirección y se repitió la regresión sobre las imágenes finales. También se eliminó la dependencia de alias fijos de laboratorio al comprobar la IP real de ambos servicios. El manifiesto registra las imágenes finales y los hashes de código. La lógica del dominio de conciliación y el archivo de dependencias conservan sus huellas de rc.2.

La preparación técnica corresponde al mecanismo verificado en el clon. La futura operación requiere el preflight del destino, el aprovisionamiento de una política específica con sus recursos reales, acceso histórico validado y aprobación expresa. No se efectuó el corte ni se publicaron puertos.
